fs.readFile() is asynchronous, so Node.js starts the file-reading operation and continues executing the next lines of the program. The file content is handled later through the callback when the reading is complete. Therefore, the message outside the callback can be printed before the file content. In contrast, fs.readFileSync() is synchronous and blocks the program until the complete file has been read. After the synchronous operation finishes, only then does Node.js execute the next line.
If two people try to write to the same notes.txt file at exactly the same time, both processes may access the file simultaneously. The order in which the notes are saved may be unpredictable. In some situations, simultaneous writes can also cause problems such as overlapping or corrupted content, depending on the system and file operation. A simple file-based application does not provide proper coordination between multiple users. A real application would usually use a database, file locking, or another mechanism to safely handle concurrent writes.
